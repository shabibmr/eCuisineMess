# 03 — Database Design (MariaDB)

Source of truth: [`database/schema.sql`](../database/schema.sql) — declared accurate. This doc explains it; if they ever differ, the SQL wins and this doc is the bug.

- Tables: **14**. Database: `ecuisine_mess` · charset `utf8mb4` / `utf8mb4_unicode_ci` · engine InnoDB
- **Primary & foreign keys: `CHAR(36)` UUID**, generated by the API (`uuid4`). Seed rows use fixed UUIDs.
- **No `*_code` columns.** Natural keys are unique names.
- Timestamps: `created_at` (default `CURRENT_TIMESTAMP`), `updated_at` (`ON UPDATE CURRENT_TIMESTAMP`) on masters.

## 2. Tables

| Table | Purpose | Uniqueness | Delete behaviour |
|---|---|---|---|
| `mess_meal_times` | **Per-cuisine** B/L/D windows (3 rows per cuisine; defaults 07–10, 12–15, 19–22) | (`cuisine_id`,`meal_type`) `uk_cuisine_meal` | cascades with cuisine; otherwise edit only |
| `mess_item_categories` | Item category master | `category_name` | items → `category_id = NULL` |
| `mess_uoms` | Units of measure (Nos, Plate, Bowl, Cup…). **Seed-only master — no app CRUD** | `uom_name` | `ON DELETE RESTRICT` from items |
| `mess_items` | Item master; `uom_id` NOT NULL FK → `mess_uoms` (the old free-text `unit` column is gone) | — | referenced items are deactivated by the API (BR-I3) |
| `mess_cuisines` | Cuisine master | `cuisine_name` | block in API if referenced (BR-C2) |
| `mess_cuisine_items` | Allowed items per cuisine + `default_qty` | (`cuisine_id`,`item_id`) | cascades with cuisine/item |
| `mess_members` | Member + RFID + validity | `rfid_tag` | cuisine delete → NULL; block if billed (BR-M7) |
| `mess_daily_menus` | Menu header per date × cuisine × meal | (`menu_date`,`cuisine_id`,`meal_type`) | cascades items |
| `mess_daily_menu_items` | Menu lines (`quantity`) | — | cascades |
| `mess_bills` | Issued token (always 0.00) | `bill_number` | **never deleted**; cancel flips `status` |
| `mess_bill_items` | Snapshot lines (`item_name` copied) | — | cascades with bill |
| `mess_users` | Staff logins | `username` | — |
| `mess_user_sessions` | Opaque bearer tokens | `token` | cascades with user |
| `mess_organizations` | Standalone organization master (TRN, bilingual header print fields, currency, contacts) | `org_name` | deleted via API |

### Allowed values (enforced by API, not DB `ENUM`)

| Column | Values |
|---|---|
| `meal_type` (`mess_meal_times`, `mess_daily_menus`, `mess_bills`) | `BREAKFAST`, `LUNCH`, `DINNER` |
| `mess_members.status` | `ACTIVE`, `EXPIRED`, `SUSPENDED` |
| `mess_bills.status` | `SERVED`, `CANCELLED` |

> The mock-ui and spec use `B`/`L`/`D` shorthand. The **wire format and DB use the full words**; map to the letter only for display and token prefixes.

## 3. Indexes

| Index | Table | Why |
|---|---|---|
| `idx_rfid` (+ unique) | `mess_members` | Tap lookup (hot path) |
| `idx_member_date_meal` | `mess_bills` | Duplicate-serve check |
| `idx_bill_date_meal` | `mess_bills` | Counters, headcount, token sequence |
| `uk_daily_menu` | `mess_daily_menus` | Menu lookup at tap |
| `idx_session_token`, `idx_session_expires` | `mess_user_sessions` | Auth + purge |

**Suggested additions** (not yet in schema — propose before adding):

| Index | Reason |
|---|---|
| `mess_bills (bill_date, bill_time)` | Time-based report, register ordering — UUID PKs are **not** chronological |
| `mess_members (validity_end)` | Expiring-members report |
| `mess_daily_menu_items (menu_id, item_id)` **UNIQUE** | Enforce BR-D3 in the DB |
| `mess_bills (token_number, bill_date)` | Guard against duplicate tokens (BR-B5) |

## 4. UUID strategy — consequences to remember

1. **Never `ORDER BY id`** to get "latest" — UUIDv4 is random. Order by `created_at` or (`bill_date`,`bill_time`). *(Current `list_bills` does `ORDER BY b.id DESC` — a bug, see [08](08-gap-analysis-roadmap.md).)*
2. IDs are **strings** in JSON and Dart (`String id`). Never parse to int.
3. `CHAR(36)` with `utf8mb4_unicode_ci` is acceptable at this scale. If bills grow into the tens of millions, consider `UUID` native type (MariaDB ≥ 10.7) or `BINARY(16)`.
4. FK columns are always `CHAR(36)`, same collation as the PK they reference.
5. The API generates IDs; clients send none on create.

## 5. Token & bill numbering

- `token_number`: `{B|L|D}-{NNNN}`, running count per `bill_date` + `meal_type`, resets daily.
- `bill_number`: globally unique operational number (format owned by the API).
- Numbering must be generated **inside the issue transaction** with the sequence row locked (e.g. `SELECT … FOR UPDATE` on the day's max, or a `mess_counters` table) so two counters cannot mint the same token. Current implementation uses `COUNT(*)` — see [08](08-gap-analysis-roadmap.md).

## 6. Migrations

`database/migrations/` — plain numbered SQL, applied manually or via a script.

| File | Purpose |
|---|---|
| `001_mess_users.sql` | Users + sessions |
| `002_mess_item_categories.sql` | Category master, backfill, FK |
| `003_uuid_ids_drop_codes.sql` | **Breaking** UUID cut-over; drops codes, **drops and reloads** the DB |
| `004_mess_uoms.sql` | `mess_uoms` + `mess_items.uom_id` (replaces the `unit` text column) |
| `005_cuisine_meal_times.sql` | `mess_meal_times.cuisine_id` (NOT NULL, FK CASCADE) + `UNIQUE(cuisine_id, meal_type)`; replaces the 3 global rows with 3 default windows per cuisine. Idempotent |

Rules for new migrations:

- Name `NNN_short_description.sql`, next free number, never edit an applied file.
- Idempotent where practical (`IF NOT EXISTS`, `INFORMATION_SCHEMA` guards).
- Every migration is mirrored into `schema.sql` in the same commit (`schema.sql` always describes a fresh install).
- Seed changes go in `seed.sql`.
- Back up first: `mysqldump --routines --single-transaction ecuisine_mess > backup.sql`.

## 7. Seed data (`database/seed.sql`)

Per-cuisine meal times (5 cuisines × B 07:00–10:00 / L 12:00–15:00 / D 19:00–22:00 = 15 rows), five categories (Main, Side, Bread, Beverage, Dessert), UOMs, items (with `uom_id`), cuisines + mapping, sample members, `admin` / `admin123` (bcrypt). Menus for demo dates are seeded for counter testing.

## 8. Backup & maintenance (Windows)

```powershell
# Nightly backup (Task Scheduler)
& "D:\xampp\mysql\bin\mysqldump.exe" -u root --single-transaction --routines ecuisine_mess `
  | Out-File -Encoding utf8 "D:\backups\ecuisine_mess_$(Get-Date -Format yyyyMMdd).sql"

# Purge expired sessions (weekly)
& "D:\xampp\mysql\bin\mysql.exe" -u root ecuisine_mess -e "DELETE FROM mess_user_sessions WHERE expires_at < NOW();"
```

Create a dedicated DB user for the API in production (`GRANT SELECT,INSERT,UPDATE,DELETE ON ecuisine_mess.* …`); stop using `root` with an empty password.
